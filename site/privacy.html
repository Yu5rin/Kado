プライバシーポリシー

SlideinaCalendar ／ 2026年9月21日

要点

  • 予定・タスクなどのデータは利用者の端末内にのみ保存します
  • 予定やタスクの中身そのものを、作者や第三者のサーバーへ送信することはありません
  • ただし、更新の確認・実働日データの取得のために、Google 以外ともいくつか通信します。 送っている内容は下の「通信先」に挙げたとおりです
  • 解析・広告・トラッキングの仕組みは入れていません

取り扱う情報

予定・タスク 端末内のデータベースに保存します。Google と同期している場合は、 利用者自身の Google カレンダーおよび Google ToDo リストとの間でのみやり取りします。 同期している予定・タスクについては、差分の判定に使うため、Google から受け取った 生のデータ（画面には出していない参加者のメールアドレス、会議の URL、説明欄の全文を 含みます）も、暗号化しないまま端末内のデータベースにそのまま保存しています。 「バックアップ」で書き出したファイルにも同じ内容がそのまま入ります。
実働日データ 利用者が読み込んだファイル、または配信元から取り込んだ内容を端末内に保存します。 外部（作者や第三者のサーバー）へ送信することはありません。
認証情報 Google の認可で受け取ったトークンを、OS の仕組み（Windows では DPAPI）で 保護して端末内に保存します。作者はこれを受け取りません。

通信先

Google 以外にも、次の通信を行います。いずれもアプリの動作に必要な範囲だけで、 予定・タスクなど利用者のデータそのものを Google 以外の送信先へ渡すことはありません。

更新の確認
（api.github.com）		 アプリの起動のたびと、⚙メニューの「更新を確認…」を押したときに、 新しい版が出ていないかを確かめます。この通信で GitHub 側に渡るのは、通信元の IP アドレスと、アプリの版を含む User-Agent（名乗り）です。リポジトリが非公開の あいだはこの通信は失敗するだけで、アプリの動作には差し支えません。
更新の取得
（github.com ／ *.githubusercontent.com）		 「更新する」を選んだときだけ、新しい実行ファイルを取ってきます。取得先は HTTPS かつ GitHub の配信先であることを確かめてから通信します。
実働日データの配信元
（利用者が設定した HTTPS の URL）		 ⚙メニューから取り込みを選んだとき、また設定で自動更新を有効にしている場合は 1日1回、配信元へ実働日データを取りに行きます。配信元へ渡るのは そのファイルを求める通信だけで、利用者のデータは送りません。

Google のデータの利用について

本アプリが Google API から受け取った情報の利用および他アプリへの提供は、 Google API サービスのユーザーデータに関するポリシー（限定使用の要件を含む）に従います。

要求する権限と、その用途は次のとおりです。

calendar.events 予定の読み取りと書き込み。アプリ上での追加・変更・削除を反映するため。
calendar.readonly カレンダーの一覧、表示名、色の読み取り。左パネルの一覧に出すため。
calendar.app.created 本アプリが作成したカレンダーの管理。
tasks タスクの読み取りと書き込み。

これらの情報を、機能の提供以外の目的（広告、販売、機械学習モデルの学習など）に 使うことはありません。

データの削除

  • アプリ内から連携を解除すると、保存しているトークンを削除し、 Google 側の許可も取り消します
  • 端末内のデータは、保存先のフォルダーを削除すれば消えます
  • Google アカウント側からは アカウントにアクセスできるアプリ でいつでもアクセス権を取り消せます

変更

内容を変更した場合は、このページを更新します。
