# 実機で確かめること

CI は Linux で回しているので、確認できるのは**コンパイルが通ることとテストが通ること**
まで。WPF の画面を組み立てる処理、Windows の仕組みを使う処理（DPAPI・Mutex・
名前付きパイプ）、そして Google との実際のやり取りは、**Windows で動かすまで分からない**。

上から順に進める。つまずいたら、その行の「だめなとき」を見る。

## 0. 手に入れる

**[Releases](https://github.com/Yu5rin/Kado/releases/latest) から落とす**
のがいちばん早い。`.exe` をそのまま叩けば動く（.NET を入れなくてよい）。
`.zip` は展開先を自分で決めたいとき用。170MB ほどあるのは .NET のランタイムを
同梱しているため。

すでに入れてあるなら、**⚙ → 設定… →「Kado について」→「更新を確認…」**でも上げられる。更新機能が見にいくのは
Releases なので、Actions の Artifacts だけでは新しい版に気づかない。

**自分でビルドする**（.NET 10 SDK が要る）

```
git clone https://github.com/Yu5rin/Kado.git
cd Kado
dotnet run --project src/Kado.App
```

## 最優先（ここだけは先に）

下の2つは、**だめだったときの実害が大きい**。他を飛ばしてでも先に見てほしい。

### A. ピン留めすると画面が分割されるか

1. ツールバー右のピン（📌）を押す。**ウィンドウのままで押してよい。**
   押すと画面端へ寄り、そのまま画面を分割する
2. 別のアプリ（メモ帳・ブラウザなど）を開いて**最大化**する

**期待**：最大化したウィンドウが Kado の手前まででとまり、**重ならない**。

もう一度ピンを押すと、留める前の出しかた（ウィンドウ）に戻る。

**だめなとき**：重なってしまう、あるいはピンを押しても何も起きない。
要件書 2章の最重要要件なので、ここが成立しないと設計から見直しになる。
「ピンを押したが重なった」「ピンが押せない」のどちらかを伝えてほしい。

### B. 強制終了してもデスクトップが壊れないか

1. Aの状態（ピン留め中）のまま
2. **タスクマネージャーで Kado を強制終了**する
3. もう一度起動する

**期待**：起動したあと、他のウィンドウを最大化すると画面いっぱいになる。

**だめなとき**：画面の端が削られたまま残り、最大化しても隙間が空く。
この状態は**アプリを消しても直らない**ので、そうなったらすぐ伝えてほしい。
（応急処置：画面のどこかを右クリック →「ディスプレイ設定」で解像度を変えて戻すと
ワークエリアが取り直される。）

## 1. 起動する

**期待**：3ペインの画面が出る。左にミニ月暦とカレンダー一覧、中央に月ビュー、右に選択日。

**だめなとき**：「動作を停止しました」だけが出たら、記録を見る。

```
%LocalAppData%\Kado\crash.log
```

読み込み時にだけ落ちる XAML の書き方は過去に2度やっている。`crash.log` の中身を
そのまま伝えてもらえれば直せる。

## 2. 二重起動を防げているか

もう一度 exe を叩く。

**期待**：2本目は開かず、すでに開いている窓が前に出る。畳んでいたら開く。

**だめなとき**：2本開いてしまうなら、同期が壊れる恐れがあるので先に直す。

## 3. 自分でカレンダーを作る（Google なしで使えるか）

左パネル「カレンダー」の右の **＋** を押す。名前を入れて保存。

**期待**：一覧に増える。色は既存と重ならないものが選ばれている。
行を右クリックすると「名前と色を変える」「削除」が出る。

削除を試す。中に予定が入っていれば「別のカレンダーへ移ります」と件数が出る。
最後の1つは消せない。

## 4. 予定とタスクを作る

月ビューのマスを**2回押す**と、その日で予定の追加が開く。

**期待**：カレンダー欄に、作ったカレンダーが**名前で**並ぶ（`local:9f1c…` のような
文字列が出ていたら不具合）。時刻は「9」「930」「9:30」でも読める。

---

以下は Google に繋いでからの確認。

クライアント設定は配布物に焼き込んであるので、**下ごしらえは要らない**。
繋いで許可するだけ。

（焼き込まずに組み立てた配布物では「Google に接続…」が押せない。
その場合は ⚙ → 設定… →「Google」→「自分のクライアント設定を使う…」から入れるか、
[`google-setup.md`](google-setup.md) の手順で焼き込んだものを作り直す。）

## 5. 繋ぐ

**ツールバーの同期の表示「Google に接続…」**（または ⚙ → 設定… →「Google」→「Google に接続…」）。

**期待**：既定のブラウザが開き、Google の許可画面が出る。許可すると画面が戻り、
**そのまま1回目の同期が走る**。右上が「同期済み HH:mm」になり、丸印が緑になる。

**だめなとき**

| 症状 | 見るところ |
|---|---|
| ブラウザが開かない | 既定のブラウザの設定 |
| 許可したのに画面が戻らない | ブラウザが `127.0.0.1` を開けているか（社内のプロキシ設定に注意） |
| 「確認されていないアプリ」 | 自分で作ったものなら「詳細」→「安全ではないページに移動」 |
| 右上が「同期できません（…）」 | 括弧の中を伝えてもらえれば原因が絞れる |

## 6. 取り込めているか

**期待**：Google カレンダーに入っている予定が月ビューに出る。左パネルのカレンダー一覧が
Google の名前と色になる。

**ここが肝心**：**終日予定の日付が1日ずれていないか。** Google 側で「9月24日だけ」の
終日予定が、こちらでも24日だけになっているか。25日まで伸びていたら不具合。

タスクも同様。**期限の日付がずれていないか。**

## 7. 送れているか

こちらで予定を1件作り、右上の同期表示を押す（または `F5`）。

**期待**：Google カレンダー側に同じ予定が現れる。タイトル・日付・時刻・場所が合っている。

続けてもう一度同期する。**期待**：右上が「変更なし」のまま。何度押しても同じ予定が
増えないこと。

## 8. 消したものが復活しないか

こちらで予定を削除 → 同期。

**期待**：Google 側からも消える。

もう一度同期。**期待**：消したものが戻ってこない。

## 9. 色を変えたら戻らないか

左パネルでカレンダーを右クリック →「名前と色を変える」→ 色を変えて保存 → 同期。

**期待**：Google カレンダー側の表示色も変わる。もう一度同期しても、こちらの色が
Google の色に戻らない。

（Google は決まった色しか持てないので、選んだ色に**いちばん近い色**に寄る。
まったく同じ色にはならないことがある。）

## 10. 繰り返しの1回だけを変えたとき

Google カレンダーで繰り返しの予定を作り、そのうち**1回だけ**を別の日に動かす
（または削除する）。そのあと同期。

**期待**：こちらでも、元の日には出ず、動かした先に出る。
**元の日と動かした先の両方に出たら不具合。**

## 11. 裏での同期

繋いだまま15分ほど置く。

**期待**：右上の時刻が勝手に新しくなる。画面が割り込んだり、エラーの窓が出たりしない。

## 12. 繋ぎ直せるか

**⚙ → 設定… →「Google」→「接続を切る」**。

**期待**：右上が「Google 未接続」、丸印が灰色に戻る。**こちらの予定は消えない。**
もう一度「Google に接続…」で繋ぎ直せる。

# v0.8.0 で足したもの

ここから下は Google に繋いでいなくても確かめられる。

## 13. 消した予定が Google に届くか（v0.7.4 の修正）

**Google カレンダーが2つ以上あるときに起きていた不具合。** 削除の記録に持ち主が
入っておらず、関係ないカレンダーへ削除を投げて 404 になり、本当の持ち主には
一度も届いていなかった。

1. Google カレンダーを**2つ以上**繋いでおく
2. 1つ目のカレンダーで予定を作り、同期する
3. 2つ目のカレンダーでも予定を作り、同期する
4. **2つ目**の予定をアプリから削除し、同期する
5. ブラウザで Google カレンダーを開く

**期待**：4で消した予定が Google 側からも消えている。もう一度同期しても戻らない。

**だめなとき**：Google 側に残っている、または次の同期で戻ってくる。
どちらのカレンダーの予定だったかを伝えてほしい。

## 14. ウィンドウの位置と大きさを覚えるか

1. ウィンドウを適当な位置・大きさにして、閉じる
2. 起動し直す

**期待**：同じ位置・同じ大きさで開く。

3. 最大化した状態で閉じて、起動し直す

**期待**：最大化で開く。そこから**元に戻す**と、最大化する前の大きさに戻る
（既定の大きさに落ちたら不具合）。

4. 最小化した状態で閉じて、起動し直す

**期待**：最小化ではなく、ふつうの大きさで開く。

5. （外付けディスプレイがあれば）そちらにウィンドウを置いて閉じ、**ケーブルを抜いてから**
   起動する

**期待**：画面の中に収まって開く。画面の外に開いて手が出せない、が起きないこと。

## 15. 年ビュー

ツールバーの「年」を押す。

**期待**：年度（4月〜翌3月）で12か月が縦に並ぶ。1行1か月で、横に1日〜月末。
上期（4〜9月）と下期（10〜3月）に見出しが付く。右端に月の実働日数。

**見てほしいところ**

- 会社配布の実働日カレンダーと**同じ形に見えるか**。休みの並びが縦に揃って読めるか
- 2月の行が28日（または29日）で終わっているか。31日まで空の枠が伸びていたら不具合
- 実働日データを取り込んでいない月の右端が「−」になっているか
- 右上の「ストリップ／カレンダー」を切り替えると12枚のミニカレンダーになるか。
  切り替えたあと**一度閉じて開き直しても、選んだほうで出るか**
- ホイールで年度が前後に動くか（月・週・日と同じ）
- 日を2回押すと、その日の月ビューに移るか

## 16. 一覧ビュー

ツールバーの「一覧」を押す。

**期待**：予定とタスクが日付順に流れる。予定のない日は「予定なし 4日」のように
**まとめて1行**になり、面が一段沈む。

**見てほしいところ**

- 予定のない日が**消えていない**か。畳んでいても日付が繋がっているか
- 今日の行に左端の線が付いているか
- 実働日の日に「実働 15日目」が出ているか
- `Ctrl`＋ホイールで前後の期間へ移るか

## 17. 実働日計算パネル

左パネルの下の「実働日計算を開く」を押す。

**期待**：2つの欄が出る。

- **期間の実働日数**：「から」「まで」を入れると実働日数が出る。**両端を含む**
  （9/14 月 〜 9/18 金 なら 5 実働日）。下に「暦日では 7 日（うち休業 5 日）」
- **N 実働日後の日付**：基準日と日数を入れると到達日が出る。基準日そのものは数えない。
  負の数を入れると遡る

**見てほしいところ**

- 手計算・会社配布のカレンダーと数が合うか
- 実働日データの範囲外を入れると「範囲外です」と断るか（黙って0を出さないこと）
- 設定で「暦日で数える」にしていても、**ここだけは実働日で数える**か

## 18. シェル統合の残り

### トレイ

**期待**：閉じるボタンを押すと窓が消え、タスクトレイにアイコンが残る。
アイコンを左クリックで戻る。右クリックでメニュー（Kado を開く／予定を追加…／―／ウィンドウ／スライド／固定／―／
左端／右端／―／今すぐ同期／設定…／―／Kado を終了）。出しかたと辺は今のものにチェックが付く（開くたびに）。

**終了はトレイのメニューか ⚙ の「Kado を終了」から。** 閉じるボタンでは終わらない。

**⚙ → 設定… →「起動と常駐」**の「閉じるボタンでトレイに入れる」を切ると、閉じるボタンで
そのまま終わるようになる。切ってから閉じて、本当に終わるかも見てほしい。

### ホットキー

他のアプリを使っているあいだに押す。

- `Ctrl`＋`Alt`＋`C` … 前に出る
- `Ctrl`＋`Alt`＋`N` … 前に出る（クイック入力用）

押せるものの一覧は **⚙ →「ショートカット…」**（F1 でも開く）。
書いてあるのに効かないものがあれば伝えてほしい。

**だめなとき**：効かないなら他のアプリに取られている。実害は無いので、
効かなかったことだけ伝えてもらえればよい。

### 画面端ホバー

トレイのメニューから「画面端に寄せる」にして、窓を隠してから画面の右端に
マウスを**0.3秒ほど留める**。

**期待**：スライドインして出る。端をただ通り過ぎただけでは出ない（誤爆防止）。

### 画面の構成が変わったとき

1. 外付けのディスプレイをつないだ状態で、スライドにして右端へ寄せ、終了する
2. ケーブルを抜く（またはノート PC を持ち出す）
3. 起動する

**期待**：今ある画面（主画面）の右端に出る／引っ込む。端にマウスを当てると出る。
`shell.log` に `startup-restore … 置き直し=はい|いいえ` が出ている。

4. 起動したまま、外付けのディスプレイをつなぐ・抜く・表示倍率を変える

**期待**：数秒のうちに、今の画面の端へ置き直る（`display-change …` が出る）。
ウィンドウにしていれば、画面の外に出たままにならない。

### ログオンで起動する設定

スタートアップに登録して、サインアウト → サインインする。

**期待**：スライドなら、起動の直後に一度出て引っ込む（`OffScreenLeft` が出る）。
そのあと端に当てると出る。引っ込まないときは `shell.log` の `SlideOut 見送り 理由=…` を伝えてほしい。

### ドック幅

ピン留め中、**画面の内側にあたる辺**（右に寄せていれば左側）をドラッグする。

**期待**：幅が変わり、手を止めると他のウィンドウがその幅に合わせて並び直す。
ドラッグ中ずっと画面じゅうが震えることはない。

### スリムパネル

**幅では切り替わらない。** ツールバーの▥（表示するパネルを選ぶ）を押し、
「スリムパネル（ひと月と、その日の予定）」にチェックを入れる。

**期待**：1列の形の4つ目のパネルが出る。上にひと月の並び、下に選んだ日の予定・
タスクが縦に続く。間の仕切りをドラッグすると上下の割り振りが変わる。

ウィンドウやピン留めの幅を狭くしても、出しているパネルが自動でスリムパネルに
化けたり、手で出したパネルが幅の都合で消えたりしないことも見てほしい
（入りきらないぶんは切れるだけでよい）。

## 19. スリープからの復帰

通知を使っているなら。予定の15分前（設定の値）をまたぐようにスリープして、起こす。

**期待**：起きた直後に通知が出る。1分待たされない。

## 20. 工程逆算（実働日計算パネル）

実働日データを取り込んだ状態で、左パネル下の「実働日計算を開く」を押す。
「工程逆算（納期から節目を逆算）」の節を見る。

**期待**

- セットが1つ（既定は「標準」＝仕様期限 −12／1次GO −9／S中日程 −5／M中日程 −2）
  出ている。「基準日（＝納期）」に日付を入れると、各節目の到達日が一覧で並ぶ
- 「＋節目」で行を足せる、行の「×」で消せる、「▲」「▼」で並び替えられる。
  名前・オフセットの書き換えはその場で反映される
- 「＋セット」でセットを増やせる、名前を書き換えられる、「セット削除」で消せる。
  窓を閉じて開き直しても、書き換えた内容とセットの選択が残っている
  （設定の表に保存されている）
- 基準日を非稼働日にしても計算できる（基準日自体は稼働日でなくてよい）
- 実働日データの範囲外まで遡る／進めるオフセットにすると、その行だけ
  「実働日データが足りません」と静かに出る（ほかの行は出たまま）
- 「結果をコピー」を押し、Excel に貼ると列（節目・オフセット・日付）が分かれて入る
- 見出しの下に「カレンダーの日をクリック＝から、Shift＋クリック＝まで」の案内が
  出ている

**見てほしいところ**：各節目の行から「予定を作る」「タスクを作る」を押すと、
その日を入れた状態で予定・タスクの編集画面が開くか（`MainViewModel` 側の配線が
入っていないと、ボタンごと出ない）。

## 21. クイック入力でタスクを入れる

クイック入力の欄（`Ctrl+Alt+N` で入れる）に、先頭へ印を付けて打つ。

**期待**

- 「todo 部品表確認」「- 部品表確認」「□ 部品表確認」「タスク: 部品表確認」の
  どれも、**予定ではなくタスクとして**入る
- 「todo 明日まで 部品表確認」のように日付語と組み合わせても、印だけを除いた
  残りが今までどおり日付として読める
- 印を付けなければ、今までどおり予定として入る
- 「終日 出張」は読めない言い回しとして止められず、そのまま（終日の）予定として
  入る（時刻を書かなければどのみち終日なので、これでよい）

**見てほしいところ**：印を付けたときに、実際にタスクとして登録されるか
（`MainViewModel.CommitQuick` 側の分岐が入っていないと、印だけ外れて予定のまま
入ってしまう）。

## 22. 自動バックアップ

`%LocalAppData%\Kado\backups\` を開いておく。

**期待**

- アプリを起動すると、少し遅れて `data-yyyyMMdd-HHmmss.db` が1本増える
  （起動そのものは待たされない）
- 同じフォルダに6本以上あるとき、起動のたびに古いものから消え、**常に5本まで**
  になる
- ⚙メニューの「復元…」でバックアップから復元する**直前**にも、置き換わる前の
  内容で1本増える

**見てほしいところ**：フォルダを削除できない・書き込めない状態（別プロセスが
掴んでいる等）でも、起動やバックアップ・復元そのものは失敗せずに続くか。

## 23. 更新の確認と、通信を確かめる入口

会社のネットワークで更新できなかった件の修正（`docs/調査記録/修正-会社のネットワークで更新できない.md`）。
CI では通信の中身をテストしているが、**実際のプロキシ・回数の上限・GitHub の転送先**は
実機でしか分からない。

**通信を確かめる**（最新版のままでよい）

1. 設定 →「Kado について」→「うまく更新できないとき」の「通信を確かめる」を押す
2. 数秒〜30秒ほどで、3行（更新の一覧・リリース情報・配布ファイルの置き場）に
   成功／失敗が出る

**期待**：自宅では3つとも「成功」。配布ファイルは 256KB ほどを受け取って切る。
ファイルは保存されない（`%TEMP%\Kado` に何もできない）。

**だめなとき**：`shell.log`（データの保存先。設定の「データ」から開ける）の
`更新の通信確認:` の行を見る。状態コード・Content-Type・転送先・例外の連鎖が出ている。
読み方は `docs/調査記録/修正-会社のネットワークで更新できない.md` の表。

**更新の確認**

1. 「更新を確認…」を押す。最新なら「最新です」
2. わざと通信を切って押す。**理由に合った文言**が出て、「リリースのページを開きますか？」と
   聞かれる（「はい」で既定のブラウザに開く）
3. 会社の回線（回数の上限を受けやすい環境）で、新しい版がある状態で押す。
   API が 403 でも「更新する」まで進めるか。このとき変更点の欄は
   「変更点を読めませんでした。リリースのページで確かめてください。」になり、
   ファイルの照合（SHA256）は省かれる

**見てほしいところ**：`shell.log` に、確認・ダウンロードの各段階が1行ずつ出ているか。
プロキシを経由する環境なら、起動ごとに1回 `更新の通信: プロキシを経由する（…）` が出る。
転送先の URL に `?sig=…` のような署名が**出ていない**こと。

## 24. 同期のあとの元に戻す・編集中の同期・消えたもの（Google に繋いで）

予定が二重になる・消える筋を直した版。Linux では Google との実際のやり取りを確かめて
いないので、次を手元で見てほしい。

1. 予定を作って同期する。**Ctrl＋Z で追加を取り消し**、同期する。→ Google 側からも
   消える。そのまま **Ctrl＋Y**（やり直し）して同期する。→ Google に**1つだけ**新しく入る
2. 予定の題を変えて同期し、**Ctrl＋Z**。同期する。→ Google の題も元に戻る
3. 予定を別のカレンダーへ移して同期（Google 側でも移っている）。**Ctrl＋Z**で戻して同期する。
   → Google 側でも元のカレンダーへ戻り、**二重にならない**
4. 同期済みの予定を削除して同期し、**Ctrl＋Z**。→ 予定が戻り、同期すると Google にも入る
5. 予定の編集画面を開いたまま、ブラウザで同じ予定の題を変えて、アプリで同期（F5）してから
   「保存」。→ 「編集中に Google 側でこの予定が変わりました。…上書きしますか？」が出る。
   「いいえ」で編集画面に戻り、「はい」でこちらの内容で上書きされる
6. 予定の編集画面を開いたまま、ブラウザで同じ予定を**削除**し、アプリで同期してから「保存」。
   → 保存されず、下の表示に「保存しませんでした」と出る。予定は復活しない
7. 予定を別のカレンダーへ移して、送られる前（同期の前）に削除して同期する。→ Google から消える
8. Google でカレンダーを**一覧から隠し**（「カレンダーの一覧」で非表示）、同期する。→
   アプリのカレンダーも予定も**消えない**
9. 繰り返しが RDATE の予定（ics 取り込みなど）をドラッグする。→ 動かず、
   「繰り返しの予定は編集画面から変えてください」と出る。編集画面の繰り返し欄は
   「Kado では表せない繰り返し（Google で編集してください）」で、日時は変えられない

**見てほしいところ**：同期の警告（右上の黄色い丸）に出る文言。「Google 上で見つからないため
送りません」「Google 側で削除されたため、こちらの未送信の変更を捨てました」が出たら、
どの予定か、そのとき Google 側はどうなっていたかを伝えてほしい。

## 25. 送るものを絞った版（Google に繋いで）

使う人が変えていないものを、Google に送らないようにした版。Linux では Google との実際のやり取りを
確かめていないので、次を手元で見てほしい。

1. Google の**カレンダーの色を Web で変え**、アプリで同期（F5）する。→ アプリの色が Web に
   追従し、**Web の色は元に戻らない**。呼び名（「自分のカレンダー名」）も同じ
2. アプリでカレンダーの色を変えて同期する。→ Web の色が一番近い色に変わる
3. America/New_York など**別の時差で作った予定**の題だけをアプリで直して同期する。→ Web で見ると、
   時刻・時差とも変わっていない（繰り返しなら、夏時間をまたいだ回の時刻も変わらない）
4. タスクを**過去の日付で完了**にして同期する。→ 完了日時が「同期した時刻」にならない。完了を取り消して
   同期すると、Web でも未完了に戻り、完了済みの一覧に残らない
5. 他の道具（メールなど）が付けた `source` を持つ予定の題を直して同期する。→ Web の「ソース」の題が
   変わらない
6. 繰り返しの予定の1回だけを動かし（Web で）、アプリで取り込んでから親の題を直して同期する。→
   動かした回が元の日に二重に出ない
7. `EXDATE` を持つ繰り返しの**開始時刻を変えて**同期する。→ 除外した回が、除外のまま
8. 他人が主催する予定、「集中時間」「不在」「勤務場所」の予定の編集画面を開く。→ カレンダー欄が
   選べず、理由が出る。サブタスク／サブタスクを持つタスクも、リスト欄が選べない
9. ファイル名の無い添付（ドライブ以外）を2件付けた予定で、1件だけ外して同期する。→ もう1件は残る
10. ゲストのいる予定と、同じ題・日時の予定を作って「重複を整理」する。→ ゲストのいるほうが残る
11. 長く繋いでいない（またはブラウザで予定を消してから 1 週間以上あけた）あとで同期する。→ Google で
    消した予定が、アプリからも消える（未送信の編集があるものは残り、警告に出る）
12. 読み取り専用の共有カレンダーを既定の入れ先にしていた状態で、1行入力から予定を入れる。→ 別の
    カレンダーに入る。すでに入ってしまった予定は、右クリックの削除で消せる
13. Google でカレンダーの購読を解除する（まだ送っていない予定がある状態で）。→ 左パネルに
    「外れた」の印が付き、警告が出る。予定は見られ、右クリックの「削除」で中身ごと手元から消せる。
    タスクリストを Google で消したときも同じ
14. 警告が出る状態で、次の同期が無事に終わっても警告が残る。設定の「警告を確認済みにする」か、同期の表示の右クリック「警告を確認済みにする」で消える（警告が無いときは右クリックしてもメニューが出ない）

**見てほしいところ**：移せないものを移そうとしたときの警告（「…カレンダーを移せません」）と、全件を
取り直したときに出る警告（「Google で見つかりません」）の文言。

## 26. 落ちない・使えなくならない（常駐の安全網）

どれも Linux のテストでは試せない（Windows の仕組みそのもの）。判断の部分は単体テストで押さえてある。

1. **添付**：Google に繋いで、予定の編集で「添付を足す」。ブラウザが開く前に、
   クライアント設定のファイルを消す／ネットワークを切る／プロキシが HTML を返す環境にする。
   → 編集画面の中に理由が出て、アプリは終わらない
2. **更新の入れ替えを止められる**：AppLocker やウイルス対策で、ダウンロードした exe の実行を止めた状態で
   ⚙ → 設定… →「Kado について」→「更新を確認…」→「更新する」。→ 「入れ替えられませんでした」「元の版に戻しました」と出て、
   元の exe で起動し直せる（`Kado.exe.failed` と `shell.log` が残る）。「入れ替えています…」が描かれる
3. **切断**：ネットワークを切って 設定の「Google」→「接続を切る」。→ 未接続になり、案内が出る。
   ネットワークを戻しても、裏の同期が勝手に再開しない（`google-tokens.dat` が無い）
4. **書き込めない保存先へのバックアップ**：読み取り専用のフォルダを選ぶ。→ 下の行に理由が出て、落ちない。
   復元で、バックアップではないファイルを選ぶ → 「Kado のデータとして読めない」と出て、何も閉じない
5. **トレイ**：タスクマネージャーで「Windows エクスプローラー」を再起動する。→ アイコンが戻る。
   ログオン直後にアイコンが出なかったときも、数秒〜1分で出る。出ていないあいだは、閉じるボタンで窓が隠れず終了する
6. **データベースがロックされている**：別のプロセス（DB Browser など）で `data.db` を開いたまま Kado を起動。
   → 「使っています」と出て、「再試行」で開ける。「壊れたデータをどけて」は出ない。ログオン直後でも前面に出る
7. **ディスクがいっぱい／書き込めない**：空きの無いドライブにデータを置いた状態で予定を足す。
   → 「保存できませんでした」と出て、アプリは終わらない
8. **シャットダウンの取り消し**：保存していない文書を開いたアプリがある状態でシャットダウンし、
   「キャンセル」する。→ Kado がトレイに戻っている（立ち上げ直される）。そのままシャットダウンすると、
   ピン留め中でもワークエリアが戻る
9. **2人のセッション**：別のユーザーで同時にサインインし、それぞれ Kado を起動して2本目を起動する。
   → 自分のセッションの Kado だけが前に出る
10. **トークンの復号**：`google-tokens.dat` を壊した状態で起動。→ 初回は何も出ず `.unreadable` が残る。
    もう一度起動して読めなければ、一度だけ「接続情報を読めなかった」と出る（最初の画面とトレイのあと）。
    その間に2本目を起動すると、すぐ前に出る

## 27. 会社のネットワークで（認証付きプロキシ・スリープ明け・常駐中の更新）

通信まわりの修正（`docs/調査記録/修正-会社のネットワークで更新できない.md` の「その後」）。
判断は単体テストで押さえてあるが、**実際のプロキシ・VPN・スリープ**は実機でしか分からない。
どれも `shell.log`（設定の「データ」から開ける）を横に開いて見る。

1. **認証付きプロキシ（407）**：Windows にログオンした資格情報で認証するプロキシの下で、
   「Google に接続…」→ 同期 → 添付を足す → 「更新を確認…」→ 実働日の「今すぐ取り込む」。
   → どれも通る。`shell.log` に `Google 通信: プロキシを経由する（…, 資格情報=ログオン中のユーザー）` と
   `更新の通信: プロキシを経由する（…, 資格情報=ログオン中のユーザー）` が1回ずつ出る。
   認証が通らないとき（ログオンしていないアカウントなど）は、右上に「プロキシの認証が必要です（407）」と出て、
   `shell.log` の `Google 同期:` の行に `応答 407 …, Proxy-Authenticate=Negotiate/NTLM` が残る
2. **社内の通信検査（証明書）**：検査が入る回線で同期する。→ 右上は「証明書を確認できません…」。
   `shell.log` に `AuthenticationException` の連鎖と `種類=CertificateProblem`
3. **画面が固まらない**：プロキシの自動検出が遅い回線（PAC のある会社）で、
   「今すぐ同期」・「Google に接続…」・添付を足す・「切断」を押す。→ 押した瞬間に画面が固まらない
   （最初の通信が数秒止まっても、他の操作ができる）
4. **「Google に接続」の待ちを中止できる**：「Google に接続…」を押してブラウザは放置する。
   右上は「接続中…」で、ボタンが「中止」。→ 押すと待ちが止まり、「Google 未接続」に戻る（5分待たなくてよい）。
   「切断」も、取り消しの通信中は「切断中…」で、「中止」で通信だけ諦められる
5. **認可の受け口を開けない**：セキュリティソフトで 127.0.0.1 の待ち受けを止めた状態で「Google に接続…」。
   → 「ブラウザからの戻りを受け取る準備ができませんでした（…）」と理由つきで出る。
   `shell.log` の `Google 認可:` の行に Win32 のエラー番号が残る
6. **大きい添付**：数十MB のファイルを、遅い回線で添付する。→ 30秒で切れずに上がる。
   途中でネットワークを抜く → 約1分で「アップロードが60秒間進まなかったので中止しました」と出る
7. **スリープ明けの同期**：Google に繋いだまま、ノートPCをスリープして起こす（できれば Wi-Fi が戻るまで少しかかる環境）。
   → 起きて1分足らずで、右上の時刻が新しくなる（15分〜2時間待たされない）。
   ネットワークが無いあいだに失敗が続いて間隔が延びたあと、**手で「今すぐ同期」が通れば**、
   次の裏の同期は通常の間隔（15分）に戻る
8. **スリープ明けの実働日の取得**：配信元を設定し、自動取得を入れたまま、ネットワークを切ってスリープ→起床。
   → その日のうちに、5分・15分・1時間と間隔を延ばしてやり直す（`shell.log` に `一時的な失敗のため…分後にやり直す`）。
   ネットワークが戻ったら取り込まれる。配信元の URL を存在しないものにすると、`恒久的な失敗のため、今日はやり直さない`
9. **常駐中の更新の確認**：設定の「起動したときと、動かしているあいだ1日1回…」を入れたまま、新しい版が出ているときに、
   起動から24時間たつ（または、日をまたいでスリープしてから起こす）。
   → 更新の窓は**勝手に開かない**。トレイにバルーン「新しい版 v… があります」が出て、ウィンドウ下にも出る。
   バルーンを押すと更新の窓が開く。設定で切っていれば何も出ない（`shell.log` に `更新の確認:` の行も出ない）

## 28. リンクと添付を開く・タスクの URL と添付

どれも Linux のテストでは試せない（右クリックメニューの出し分けと、ブラウザ・エクスプローラーの起動）。
判断の部分（何を開いてよいか、実行形式の扱い、見つからないとき）は単体テストで押さえてある。

1. **予定のリンク**：URL を入れた予定を、月・週（終日と時間軸）・日・一覧・右ペイン・年のどれかで右クリック。
   → 「編集」の下に「リンクを開く」が出て、押すと既定のブラウザで開く。URL の無い予定には**項目ごと出ない**。
   `ftp://…` や `www.example.com`（http が付いていない）の予定にも出ない
2. **予定の添付**：Google に繋いで添付を足した予定を右クリック。→ 「添付を開く」の右に、ファイル名が並ぶ
   （1件でも子メニュー）。押すとブラウザで開く。添付の無い予定には出ない
3. **タスクのリンクと添付**：編集画面で URL と添付（ファイル・フォルダ）を付けたタスクを、月・週・日・一覧・
   右ペインで右クリック。→ 「リンクを開く」「添付を開く」が、「別のリストへ移す」の下に出る。どちらも無いタスクでは
   項目ごと出ない（並び全体は「30. 右クリックメニュー」）
4. **タスクの編集画面**：「ファイルを追加…」で複数のファイルを選べる／「フォルダを追加…」でフォルダを選べる。
   同じ場所を2回足しても1件。「外す」で場所の記録だけが外れる（ファイルは消えない）。一覧の行を押すと開く。
   欄の近くに「URL と添付は Kado だけに保存され、Google には送られません」が出る
5. **見つからない**：添付したファイルを移動してから、一覧の行（編集画面）と右クリックのメニューで開く。
   → 開かず、「見つかりません：（パス）」が出る（編集画面は一覧の下、右クリックは右上の状態表示）
6. **実行形式**：`.exe` や `.bat` を添付して開く。→ **実行されず**、エクスプローラーが開いてそのファイルが
   選ばれた状態になる。「実行形式のファイルは開かず…」と出る
7. **落ちている共有フォルダ**：`\\落ちているサーバー\共有\ファイル` を添付して、開く。→ 開くのに時間がかかっても、
   画面は固まらない（確認は別のスレッドで行う）。最後に「見つかりません」が出る
8. **Google に送られない**：Google に繋いだタスクに URL と添付を付けて同期する。→ Web の Google ToDo の
   詳細に何も増えない。Web で題を直して同期しても、アプリの URL と添付は残る。Ctrl＋Z で付ける前に戻り、
   Ctrl＋Y で戻る

**見てほしいところ**：右クリックメニューの見た目が、他の項目（枠・色・角丸）と揃っているか。
「添付を開く」の子メニューが、画面の端でも切れずに開くか。ライト・ダークの両方。

## 29. タスクの繰り返し（Kado 独自）

繰り返しは Kado だけが持ち、Google には送らない（Google Tasks の API に繰り返しの欄が無い）。完了にすると
Kado が次の回を新しいタスクとして作る。次の期限の計算・元に戻す・同期は単体テストで押さえてある。
ここでは、画面の見た目と、実際の Google との往復を確かめる。

1. **編集画面**：期限の下に「繰り返し」の選択が出る。期限が木曜なら「毎週 木曜日」「毎月 24日」「毎年 9月24日」と
   具体的な文言になり、期限を動かす（日付欄・「今日・明日・来週」）と文言が変わる。実働日基準の4つ
   （週始め・週終わり・月初・月末）は文言が変わらない。小さく「繰り返しは Kado だけで動きます。…二重になります」が出る
2. **付けられない条件**：「期限を付ける」を外す → 選択が灰色になり「繰り返しは、期限を付けると選べます」が出る。
   サブタスク（Google のアプリで作った子タスク）を開く → 選べず「サブタスクには繰り返しを付けられません」が出る。
   期限を消して保存したタスクの繰り返しは外れる
3. **ComboBox の出し直し**：繰り返しを選んだまま期限日を動かしても、選択が「繰り返さない」に飛ばない
   （選択肢の差し替えで null が来ても無視する作り。WPF の挙動なので実機で）
4. **↻ の印**：繰り返し付きのタスクの題名の後ろに薄く「↻」が付く。右ペイン・月のチップ・一覧・週と日の終日欄の
   すべてで。ライト・ダークで読めるか、チップの幅で題名が切れすぎないか。完了したほうのタスクには付かない
5. **完了にする**：右ペインのチェック・月ビューのチップの右クリック「完了にする」・編集画面で完了にして保存の
   3通りで、状態表示に「タスクを完了にしました。次は 10/13(月)」が出て、次の回が一覧に増える。
   Ctrl＋Z を **1回** で、完了が戻り、繰り返しが戻り、次の回が消える。Ctrl＋Y でまた作られる
6. **完了の取り消し**：完了にしたほうのチェックを外す → 次の回は消えず、何も増えない
7. **実働日基準**：設定で実働日を読み込んだ状態で「毎月の月末」「毎週の週始め」を試す。月曜が会社の休みの週で
   火曜になること、設定の「週の始まり」を月曜・日曜と変えて週終わりが変わること
8. **Google に繋いで（Kado の中で完了）**：繰り返しのタスクを完了にして同期する。→ Web の Google ToDo に、
   完了したタスクと、次の回（新しいタスク）が並ぶ。詳細に繰り返しの印は付かない（付けられない）。
   完了にして **すぐ** Ctrl＋Z した場合と、同期のあとで Ctrl＋Z した場合の両方：次の回が Google からも消える
9. **Google に繋いで（Google 側で完了）**：Google のアプリや Web で、Kado の繰り返しタスクを完了にして、
   Kado で同期する。→ 次の回が Kado に増え、**その同期のうちに** Google にも作られる（2回同期する必要は無い）。
   同期のあと、下のステータスに「同期しました。繰り返しの次の回を作りました：題名 10/13(月)」が出て、数秒で消える。
   **右上の同期の表示は「警告」にならない**（「同期済み」のまま。警告の欄にも出ない）。もう一度同期しても増えない
10. **二重**：Google のアプリで同じタスクに Google 側の繰り返しを付けると、Kado の繰り返しと併せて二重になる
    （案内の一行のとおり。Google 側の繰り返しは Kado からは見えない）。実際にどう見えるか確かめる
11. **月末・閏日**：期限 1/31 の「毎月 31日」を完了にし続ける → 2/28、3/31、4/30 と進み、ずれていかない。
    期限 2/29 の「毎年」は閏年でない年は 2/28 に寄せ、次の閏年に 2/29 に戻る
12. **既存のデータ**：V13 へ上げた直後、これまでのタスクがそのまま表示され、「↻」が付かない（繰り返しは空）

**見てほしいところ**：選択肢のドロップダウンが長い文言で切れていないか（幅 248）。「繰り返し」の欄が
サブタスクで灰色のまま理由が読めるか。ライト・ダークの両方。

## 30. 右クリックメニュー（予定・タスク・日付と空き時間）

メニューは3種類を全部の画面で共有する（`Themes/Controls.xaml` の `EventContextMenu`・`TaskContextMenu`・
`TaskRowContextMenu`（右ペインのタスクの行）・`DayContextMenu`）。並び・出し分け・押したときの動きは単体テストで
押さえてあるが、**WPF が実際にメニューをどう開くか**（どのメニューが出るか、子メニュー、灰色とツールチップ、
時間帯の時刻）は Linux では試せない。起動した直後に落ちないこと（辞書の読み込み）が、いちばん先に見るところ。

**並び**（上から）

- 予定：編集…（編集できなければ「詳細を見る…」）／リンクを開く／添付を開く ▸（あるときだけ）／―／別のカレンダーへ移す ▸／
  複製／題名と日時をコピー／―／削除
- タスク：完了にする（完了済みは「完了を取り消す」）／編集…／リンクを開く／添付を開く ▸（あるときだけ）／―／期限を変える ▸／
  別のリストへ移す ▸／複製／題名をコピー／―／削除。右ペインの行だけ、削除の上に「上へ／下へ」が区切り線で分けて入る
- 日付・空き時間：予定を追加…／タスクを追加…／―／1日で見る／週で見る／月で見る
  （今いるビューと同じものは出ない）

1. **起動**：起動してすぐ、画面が出る（`StaticResource` の前方参照・暗黙スタイルの読み込み順で落ちていないか）。
   月・週・日・年・一覧を順に開いて、どれも落ちない
2. **予定のメニュー（6か所）**：月のチップ・週と日の終日レーン・時間軸のブロック・一覧・右ペインの行・日付の行の
   ラベル（仕様期限など）のそれぞれで右クリック。→ 全部**同じ並び**
3. **複製**：予定を右クリック →「複製」。→ 編集画面は開かず、同じ日・同じ時刻・同じカレンダーに同じ題名の予定が1件増え、
   下のステータスに「複製しました」。Ctrl＋Z で消える。繰り返しの予定の2回目以降の回で「複製」→ その日だけの
   単発の予定になる（繰り返しの印が付かない）。Google に繋いで同期 → Web の Google カレンダーに新しい予定として
   出る（ゲスト・会議 URL・添付は付かない）。元の予定は変わらない
4. **別のカレンダーへ移す ▸**：子メニューに、書き込めるカレンダーが左パネルと同じ並び・同じ色見本で出る
   （今のカレンダー・読み取り専用・「Google から外れた」ものは出ない）。選ぶ → 予定の色が変わり、同期で
   Google 側も**移る**（消えて作り直されない：ゲスト・会議 URL・添付が残る）。Ctrl＋Z で戻る。
   他人が主催する予定・集中時間などは、子メニューの項目が**灰色**で、ツールチップに理由が出る
5. **題名と日時をコピー**：貼り付けると「10/6(火) 9:00–10:00 打ち合わせ（場所）」の形。終日は「10/6(火) 終日 題名」、
   複数日は「10/6(火)–10/8(木) 題名」。繰り返しの予定は右クリックした回の日付。他のアプリがクリップボードを
   掴んでいるとき（リモートデスクトップのクリップボード共有中など）は「コピーできませんでした」と出る
6. **編集できない予定**：読み取り専用のカレンダー（祝日・他人から共有されたもの）の予定、Google のメールから作られた
   予約・誕生日、他人が主催する予定を右クリック。→ 先頭が「詳細を見る…」で、押すと**読み取り専用の編集画面**が開く
   （上に理由・欄は触れない・「保存」「削除」は出ず、「閉じる」だけ）。「別のカレンダーへ移す」は灰色でツールチップに理由。
   「削除」は、いまできるものだけ押せる（Google 側で作られた予定は削除できる。読み取り専用のカレンダーの、
   Google から受け取った予定は灰色）。「複製」「題名と日時をコピー」は使える（複製先は書き込める既定のカレンダー）。
   ダブルクリックでも同じ読み取り専用の画面が開く。灰色の項目にマウスを載せるとツールチップが出るか
7. **期限を変える ▸**：「今日」「明日」「次の実働日」「来週の週始め（最初の実働日）」「期限なし」。いまの期限と同じ項目は
   灰色。実働日を読み込んだ状態で、休みの日をまたぐ日付になっているか（金曜に「次の実働日」→ 連休明け）。設定の
   「週の始まり」を変えて「来週の週始め」が変わるか。繰り返し付きで「期限なし」→ ↻ が外れ、状態表示に
   「繰り返しも外れました」。Ctrl＋Z で期限も繰り返しも戻る。月ビューのドラッグで期限を動かしたときと、結果が同じ
8. **別のリストへ移す ▸**：書き込めるタスクリストが左パネルと同じ並び・色で出る。サブタスク・サブタスクを持つタスクは
   項目が灰色でツールチップに理由。Google に繋いで同期 → Web の Google ToDo でもリストが移る
9. **タスクの複製・題名をコピー**：複製 → 未完了の同じタスク（URL・添付・繰り返しも）が増える。サブタスクの複製は
   親なし。題名をコピー → 「10/6(火) 期限 題名」（期限が無ければ題名だけ）
10. **日付・空き時間のメニュー（6か所）**：月のマスの空いた所・週の日見出し・週と日の時間帯の空いた所・年の日付・
    一覧の日付見出しと空き・右ペインの一覧の空いた所で右クリック。→ 同じ並びのメニューが出る。**予定やタスクの上で
    右クリックしたときは、その予定・タスクのメニューだけが出て、日付のメニューは出ない**（月のチップ・時間軸のブロック・
    終日レーンの予定・一覧の予定・右ペインの行・日付の行のラベルのすべてで）
11. **時間帯の時刻**：週・日ビューの時間帯の空いた所を、13:20 あたりで右クリック →「予定を追加…」。
    → 13:15 開始・14:15 終了の編集画面が開く（15分に丸める）。列の端・時間軸をスクロールした状態でも、
    右クリックした位置の時刻になる。別の時刻で2回続けて試して、前の時刻が残らないか
12. **見るメニュー**：今いるビューと同じ項目が出ない（月ビューでは「月で見る」が無い、など）。右ペインは
    ビューを切り替えても出し分けが追従する（月ビュー → 週ビューに切り替えて右ペインを右クリック）
13. **タスクを追加…**：期限がその日のタスクの編集画面が開く
14. **ショートカットの表示**：右クリックメニューに Del や Ctrl＋D などの表記は付けていない（実装に対応するキーが無いため。
    Delete は右ペインで行を指しているときだけ効く）。キーを添えているのは ⚙ のメニューだけ

**見てほしいところ**：メニューの見た目が他の項目（枠・色・角丸）と揃っているか（暗黙スタイルの引き継ぎ）。
子メニューが画面の端でも切れずに開くか。色見本の丸み。灰色の項目の濃さ（読めるか）。ライト・ダークの両方。

## 31. 自動更新（裏で落として、手が空いたときに入れ替える）

CI では判断（`AutoUpdatePolicy`・`StagedUpdateCheck`）しか試していない。**実際の入れ替え・再起動・
操作の無い時間・トレイの知らせ**は実機でしか分からない。試すには、いまより新しい版が
Releases に公開されている必要がある（下書きは配られない）。試験用に、版を1つ古くした exe を
書けるフォルダ（Program Files 以外）へ置いて起動するとよい。記録は `shell.log` の `自動更新:` の行。

**準備**：設定 →「起動と常駐」の「自動で更新する」が入っていること（既定）。

1. **裏で落とす**：古い版を起動する。→ 更新の窓は出ず、画面も固まらない。`shell.log` に
   `自動更新: 新しい版 vX.Y.Z を見つけた` → `落として照合した（SHA256 一致）` → `入れ替え待ちにした`。
   データの保存先の `updates\`（既定は exe の隣の `data\updates\`）に `Kado-vX.Y.Z.exe` ができている
2. **手が空いたときに入れ替わる**：入れ替え待ちのまま、10分以上キーボードにもマウスにも触れずに放っておく
   （別のアプリを見ていてもよい）。→ 1分おきの見回りで、勝手に終了して新しい版が立ち上がる。
   **次の場合は入れ替わらず**、`shell.log` に `入れ替え待ち。…ので待っている` が出る：
   - 10分に届かない（途中でマウスを動かすと数え直し）
   - 編集画面・設定・更新の窓のどれかが開いている（開いたまま10分放っても入れ替わらない）
   - 右クリックのメニューやコンボボックスのドロップダウンを開いたまま
   - 同期の最中（ツールバーの同期の表示が「同期中…（押すと中止）」になっている間）
   閉じる／終わるとその後の見回りで入れ替わる
3. **窓の状態が戻る**（2の入れ替えのあとで）。次のそれぞれの状態で放っておき、新しい版が立ち上がったあとの姿を見る
   - ウィンドウの位置と大きさ（最大化も）：元どおり
   - ピン留め（画面端に固定）：固定のまま、ワークエリアも削れたまま戻る（他のウィンドウを最大化して確かめる）。
     入れ替わった直後に、ワークエリアが削られたまま残らず、固まらないこと
   - スライド：隠れた状態で戻り、端に寄せると出てくる
   - トレイに入れていた（閉じるボタンで隠した）：**窓が前へ出てこない**（一瞬見えて消えるのは許容。
     見えたままなら `--keep-hidden` の経路を疑う）
4. **更新したことの知らせ**：入れ替わった直後、トレイのバルーンに「Kado を vX.Y.Z に更新しました」が
   **一度だけ**出る。押さずに消えても、Kado を再起動してもう一度出ることはない。
   バルーンを押す → 変更点の窓が開く。本文は Markdown として整形されず、`##` や `|` がそのまま見える
   （更新の窓と同じ）。本文が空のリリースなら「変更点はリリースのページをご覧ください。」と
   「リリースのページを開く」が出る
5. **終了して、次の起動で入れ替わる**：1の状態（入れ替え待ち）で、トレイの「終了」を選ぶ。→ その場では
   何も入れ替わらず、再起動もしない。もう一度 Kado を起動する → **メインウィンドウが出る前に**入れ替わり、
   新しい版が立ち上がる（`shell.log` に `入れ替え待ちの vX.Y.Z がある。起動の最初に入れ替える`）。
   サインアウト・シャットダウンで終わった場合も、終わるときは何も入れ替わらず、次のログオンで起動した
   ときに入れ替わる。シャットダウンが他のアプリに取り消されたときは、これまでどおり立ち上げ直して常駐を続ける
6. **控えを捨てる**：入れ替え待ちの状態で次のどれかを試す。いずれも `shell.log` に
   `控えを捨てる。<理由>` が出て、普通に起動する
   - `updates\` の exe を消す／中身を1バイト書き換える（SHA256 が合わない）
   - 手で新しい版に差し替えてから起動する（控えの版がいまの版以下）
7. **403 の回線では自動にならない**：会社の共有回線など、API が 403 になる環境で起動する（または
   `api.github.com` だけを遮断する）。→ 自動では落とさない。`shell.log` に
   `SHA256を取れていないため自動では入れ替えない（通知だけにする）`。起動時は更新の窓が、
   常駐中は通知が出て、「更新する」で今までどおり更新できる（ファイルの照合は省かれる旨が窓に出る）
8. **設定でオフ**：設定 →「自動で更新する」を切る。→ 新しい版が見つかっても落とさず、起動時は更新の窓、
   常駐中は通知（今までどおり）。入れ替え待ちがあるときに切って再起動すると、控えが捨てられる
9. **手で更新するとき、控えを使う**：入れ替え待ちがある状態で、⚙ →「更新を確認…」→「更新する」。
   → 落とし直さずにすぐ入れ替わる（窓に「落としてある版で入れ替えています…」と出る。
   `shell.log` に `更新のダウンロード: 開始` が出ない）
10. **落とすのに失敗したとき**：落とす途中でネットワークを切る。→ `shell.log` に
    `落とせなかったので、通知だけにする`、常駐中なら通知が出る。`updates\` に書きかけのファイルが
    残らない。次の確認（常駐中は1日後、起動時は次の起動）でまた試す
11. **入れ替えに失敗したとき**：入れ替え待ちの状態で `Kado.exe` を読み取り専用のフォルダ相当にする、または
    ウイルス対策で新しい exe の実行を止める。→ 元の版へ戻って起動し、`この版は自動では入れ替えない` が出て、
    以後その版は自動では落とさない（手で更新するのは使える）。**exe が壊れたまま残らない**こと

**見てほしいところ**：入れ替わる瞬間に、編集中の入力・開いているメニューを巻き込んでいないか。
複数モニタ・高 DPI での復元位置。入れ替え直後にタスクバーのアイコンが二重にならないか。

## 32. データの保存先（exe の隣の `data`）と引っ越し

CI では判断（`DataLocation.Decide`）と、Linux 上の一時フォルダでの写し（`DataMigration`）までしか
試していない。**Windows のフォルダの権限・DPAPI・自動起動の登録・単一ファイルの exe の場所**は実機でしか分からない。
記録は `shell.log` の `保存先:` の行。以前の版（`%LOCALAPPDATA%\Kado` に予定とタスクが入っているもの）を
使っていた PC で試すのが確実。

1. **初回の引っ越し**：以前の版のデータがある PC で、新しい exe を書けるフォルダ（例：`D:\Apps\Kado`）に置いて起動する。
   → 予定・タスク・設定・Google の接続がそのまま見える。exe の隣に `data` ができ、`data.db`・`google-tokens.dat`・
   `backups` などが入っている。`shell.log` に `保存先: …から…へ引っ越した（元は残してある）`。
   2回目以降は `保存先: D:\Apps\Kado\data` だけが出て、写し直さない
2. **元のフォルダが残る**：`%LOCALAPPDATA%\Kado` が消えていない。中に `移しました.txt`（いつ・どこへ）があり、
   `data.db` はそのまま。新しい場所で予定を1件足しても、元の `data.db` は変わらない
3. **設定画面**：設定 →「データ」に「データの保存先」としてパスが出て、「フォルダを開く」でエクスプローラが開く。
   「Kado を終了してから、exe と data フォルダをまとめて新しい PC にコピーしてください」の案内が出ている
4. **Program Files に置いたとき**：exe を `C:\Program Files\Kado\` に置いて起動する（管理者でコピーが要る）。
   → 起動できて、データは従来の `%LOCALAPPDATA%\Kado` のまま。設定の「データの保存先」に
   「exe のフォルダに書き込めないため、こちらを使っています」。`shell.log` に同じ理由。
   `Program Files\Kado\data` は作られない。自動更新は「書き込めないので手で更新」の扱いのまま
5. **写せなかったとき**：新しい `data` の置き先を一時的に読み取り専用にするなどで写しに失敗させる（任意）。
   → 今回は元の場所のまま起動し、`shell.log` に失敗の理由。`data` や `data.migrating` が残らない。
   書ける状態に戻して再起動すると、写し直される
6. **フォルダごと別の場所へ移したとき**：Kado を終了し、`Kado.exe` と `data` を別のフォルダ（別のドライブでもよい）へ
   コピーして起動する。→ 予定・タスク・設定がそのまま見える。`保存先:` がコピー先の `data`。
   元のフォルダの exe を起動しても、元の `data`（コピー前の時点のもの）が見えるだけで壊れない
7. **自動起動の書き直し**：設定の「Windows ログオン時に起動」を入れておき、手順6のように別の場所へ移して起動する。
   → 起動の少しあとに、`shell.log` に `自動起動: 登録の場所が違っていたので、いまの場所に書き直した`。
   レジストリ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の `Kado` が新しい exe を指す。
   サインアウト・サインインで新しい場所の exe が起動する。**自動起動を入れていなければ**、登録は作られない
8. **別の PC での Google の再接続**：Kado を終了し、exe と `data` を別の PC（または別の Windows ユーザー）へコピーして起動する。
   → 予定とタスクはそのまま見える。Google は「未接続」になる。1度目の起動は黙って退避
   （`google-tokens.dat.unreadable` ができる）、次の起動で「別の PC から移した場合などは、Google にもう一度接続して
   ください（予定とタスクはそのまま残っています）」と一度だけ出る。設定から接続し直すと同期できる
9. **更新が `data` に触れない**：手順1の状態で、いまより新しい版が出ているときに更新する（自動更新でも手でもよい）。
   → `Kado.exe` だけが入れ替わり、`data`（`data.db`・`google-tokens.dat`・`backups`）はそのまま。
   更新前に以前の場所の `updates` に入れ替え待ちがあった場合も、引っ越し後は `shell.log` に控えを捨てた旨が出るだけで、
   元の場所のファイルは消えない

**見てほしいところ**：2本目の起動（二重起動）で引っ越しが二重に走らないか。ウイルス対策ソフトが `data` の新規作成や
フォルダの名前変更を止めて、写しに失敗していないか（失敗しても元は無傷で、次の起動で再試行される）。

## 33. 操作性とメニューの直し（キー・確認・知らせ・設定の開き方）

キーの受け方（`Handled` にしない・操作部品に譲る）、モードレスの窓の閉じ方、メニューの並びは WPF の実際の動きなので、
Linux では試せない。単体テストと XAML・ソースの検査（`OperabilityTests`・`OperabilityWiringTests`）は通してある。
起動した直後に落ちないこと（辞書・メニューの読み込み）を最初に見る。

**キー**

1. **入力欄で文字が打てる**：クイック入力と検索欄で、`T`・`1`〜`5`・`Home`・`PageUp` を含む文字列（IME オフで
   「t1 3 5」）を打つ。→ そのまま入力され、ビューが切り替わらない・今日へ飛ばない。矢印・Home は欄の中のカーソルが動く
2. **入力欄の外**：`T`／`Home` で今日、`1`〜`5` とテンキーの `1`〜`5` でビュー切替（一覧・年・月・週・日）、
   `PageUp`／`PageDown` で前へ・次へ
3. **操作部品に譲る**：ツールバーのビュー切替（月・週・日）のボタンにフォーカスを置いて `Enter`／`Space` → ボタンが押せて
   予定の追加が開かない。左パネルの仕切りにフォーカスを置いて `←`／`→` → 仕切りが動き、選んでいる日が動かない。
   スライダー（設定の時間割の高さなど）・メニューの項目・コンボボックスでも、矢印と `Enter` がその部品の動きになる。
   何にもフォーカスが無いときの `←`／`→`／`↑`／`↓`／`Enter`／`Delete` は、今までどおり
4. **`F1`** でショートカットの一覧が開く。**`Ctrl`＋`,`** で設定。`Ctrl`＋`N` で予定、`Ctrl`＋`Shift`＋`N` でタスク、
   `Ctrl`＋`F` で検索（窓が狭く検索が畳まれているときも欄が開く）
5. **ショートカットの一覧がモードレス**：開いたまま本体のキーを試せる。`Esc` と「閉じる」で閉じる。もう一度 `F1` →
   二重に開かず前に出る。一覧の「PageUp PageDown」「← →」の説明が実際の動きと合っているか
6. **実働日計算の窓**：「閉じる」と `Esc` で閉じる。コンボボックスの一覧が開いているときの `Esc` は一覧だけ閉じる

**確認と閉じ方**

7. **繰り返しの予定を消す**：右クリックの削除・右ペインで指して `Delete`・編集画面の削除、のどれでも
   「繰り返しの予定を、すべての回、削除します。」［削除］［キャンセル］が出る。キャンセル／`Esc`／×で消えない。既定のボタンは
   キャンセル。繰り返しでない予定は確認なしで消え、Ctrl＋Z で戻る
8. **編集画面を閉じるとき**（予定・タスク・カレンダー）：何も変えずに `Esc`・キャンセル・× → 尋ねずに閉じる。
   1文字でも変えて閉じる → 「変更を破棄しますか？」［破棄する］［編集に戻る］（既定は編集に戻る）。保存・削除で閉じるときは
   尋ねない。読み取り専用の「詳細を見る…」は尋ねない
9. **`Ctrl`＋`Enter` で保存**：予定のメモ欄・タスクの詳細欄にフォーカスがある状態でも保存されて閉じる（改行が入らない）。
   保存できない状態（題名が空）では何も起きない

**タスクのチェック**

10. **右パネルのタスク**：左のチェックを押すと**その場で**完了になる（待ちが無い）。続けて別の行のチェックを押しても
    先のチェックが捨てられない。行のほかの所を1回押す → 何も起きない。ダブルクリック → 編集が開く。
    行をつまんで並べ替えるドラッグは今までどおり動く。ゴミ箱は今までどおり
11. **一覧（アジェンダ）のタスク**：丸がチェックになり、押すとその場で完了が切り替わる。行のほかの所は、
    1回押しでその日を選ぶ・ダブルクリックで編集

**知らせの帯・設定**

12. **失敗の知らせは残る**：存在しない場所へバックアップを書き出す、などで失敗させる。→ 帯が数秒で**消えず**、
    ×で消える／次の知らせで置き換わる。成功の知らせは数秒で消え、**帯の上にカーソルを置いているあいだは消えない**
13. **設定の下の行**：設定の「データ」でバックアップを保存 → 設定の窓の下に「バックアップを書き出しました（…）」が
    通常の色で出る。失敗させると赤で出る。重複整理・クライアント設定の取り込みも同じ。窓の下の行が長い文で窓を押し広げない
14. **未接続のとき**：ツールバーの同期の表示が「Google に接続…」で、ツールチップは「Google カレンダーと ToDo リストを
    同期します」。押すと設定が「Google」の分類で開く。トークンが失効した（繋ぎ直しが要る）失敗でも同じ。
    繋いでいて普通に失敗したとき（ネットワーク断）は、押すと再び同期する。走っているあいだは「同期中…（押すと中止）」
15. **設定は最後に開いていた分類を覚える**：「データ」で閉じて開き直す → 「データ」から始まる（アプリを終了するまで）
16. **◀ ▶ のツールチップ**：月ビューで「前の月」「次の月」、週で「前の週」、日で「前の日」、年で「前の年度」
17. **同期の表示の右クリック**：警告があるときだけ「警告を確認済みにする」が出る。警告が無いと何も出ない
18. **ウィンドウで左端／右端を選ぶ**：▥ のメニューの「左端」を選ぶと帯に「スライドにしたとき左端から出ます」
19. **初回の案内**（`data` を空にして起動）：「予定はマスをダブルクリックで追加できます」「Google と同期するには ⚙ → 設定… →
    Google」の2行と「閉じる」だけ。画面の出しかたは勝手に変わらない
20. **自動更新**：クイック入力に文字を打ちかけのまま10分放置 → 入れ替わらない（`shell.log` に「打ちかけの文字がある」）。
    欄を空にして10分 → 入れ替わる

**メニュー**

21. **⚙**（ツールチップ「メニュー」）：予定を追加…／タスクを追加…／―／元に戻す／やり直す／―／今すぐ同期（未接続は
    「Google に接続…」で F5 の表示が消える）／実働日計算…／Excel から実働日を取り込む…／配信元から実働日を取り込む／―／
    ショートカット…／設定…／―／Kado を終了。元に戻す・やり直すは、できないとき灰色。各項目の右にキーが出る
22. **「…」**（窓を細くして畳む）：⚙ と同じ並びに、「検索」（タスクを追加の下）、「パネル ▸」「寄せる辺 ▸」（実働日の下）が
    入る。子メニューのチェックが今の状態と合い、押すと切り替わる。ライト・ダークの両方で枠・色が他のメニューと揃うか
23. **▥**（ツールチップ「パネルと寄せる辺」）：表示するパネル（左・中央・右）／―／寄せる辺（左端・右端）
24. **トレイ**：Kado を開く／予定を追加…（前に出て編集が開く）／―／ウィンドウ／スライド／固定／―／左端／右端／―／今すぐ同期／
    設定…／―／Kado を終了。出しかたと辺に**今の状態のチェック**が付き、切り替えてから開き直すと追従する。ショートカットの項目は無い
25. **右クリックメニュー**：予定は「編集…」から始まり「別のカレンダーへ移す ▸」が「複製」の上。タスクは「完了にする」が先頭で、
    「編集…」の次にリンク・添付、区切りの後に「期限を変える ▸」「別のリストへ移す ▸」。右ペインの行は削除の上に「上へ／下へ」。
    日付は「予定を追加…」「タスクを追加…」「1日で見る」「週で見る」「月で見る」。左パネルの行は「名前と色を変える…」
    （タスクリストは「名前を変える…」）。並べ替えの知らせは「上へ移しました」「下へ移しました」
26. **言葉**：月ビューが空のとき「⚙ →「Excel から実働日を取り込む…」で会社の暦を取り込む」。実働日を取り込んだ知らせは
    「実働日 N 件」。タスクの期限の子メニューは「次の実働日」「来週の週始め（最初の実働日）」。このアプリだけのカレンダーの
    予定の添付の注意は「このアプリだけのカレンダー…」。実働日計算の節目の ▲▼× にツールチップ（上へ／下へ／この節目を削除）

## 伝えてもらえると助かること

- `crash.log` の中身（落ちたとき）
- 右上の表示の文言（括弧の中まで）
- 画面のスクリーンショット
- 「Google 側ではこうなっているのに、こちらではこう出る」という食い違い

日付が1日ずれる類は、**どちらが正で何日ずれたか**が分かれば直せる。

ピン留め（Aの項）がだめだったときは、次のどれに当たるかが分かると早い。

- ピンのボタンがそもそも出ない（画面端に寄せていないと出ない作りになっている）
- 押しても窓が動かない
- 窓は端に付くが、他のウィンドウが上に重なる
- 端に付くが、幅が思ったところと違う（タスクバーと取り合っている可能性）
