# SlideinaCalendar.Google

Google Calendar / Google Tasks の同期、OAuth、トークン保護を担当する層。

## OAuth（要件書 6.2）

`chrome.identity` は使えないので、Google Cloud Console で**「デスクトップアプリ」型の
クライアント ID を発行**し、ループバックリダイレクトで受ける。拡張機能用の ID は流用できない。

```
LoopbackOAuthFlow   127.0.0.1 の空きポートで待ち受け、ブラウザで認可画面を開き、
                    戻ってきた認可コードをトークンに交換する
GoogleTokenProvider 失効が近ければ黙って取り直す。同時に呼ばれても取り直しは1回
ITokenStore         トークンの置き場所。実装は OS の仕組みで保護する
```

### PKCE を必ず通す

デスクトップアプリ型ではクライアントシークレットを秘密にできない（配布物から読める）。
Google もそう明記している。PKCE が無いと、認可コードを横取りされたときにそのまま
交換されてしまう。

### `access_type=offline` と `prompt=consent`

この2つが無いと更新トークンが返らない。返らないまま保存すると、**開くたびに
ブラウザが立ち上がる**。`ConnectAsync` は更新トークンの無い認可を受け付けない。

### 更新トークンは上書きしない

取り直しの応答に更新トークンが含まれないことがある。そのまま上書きすると失って、
次回から繋げなくなる。`OAuthTokens.WithRefreshed` で重ねる。

### 時計は注入する

失効時刻はトークンを配る側と同じ時計で決める。実時計を直接読むと、テストで
差し替えた時計と食い違って「取り直しても使えない」状態になる（実際に踏んだ）。

## このあと実装するもの

要件書 6.3 が落としてはいけないとしている処理。

- 差分同期（syncToken）と全再同期の使い分け
- tombstone による削除伝播
- ローカル予定と Google イベントの再リンク
- 重複検出と除去
- 複数カレンダーの取得・表示 ON/OFF・並び順
- Google 標準色と自前パレットの相互変換
- 同期中の二重起動防止、バックグラウンド静音同期
- 日付・時刻の正規化
- 差分誤検知を防ぐ JSON 正規化（キーをソートして比較）

**書き戻しは `patch` で行う。** 扱わない項目を送らなければ、ゲストや通知は消えない。
ただし配列は「指定したら丸ごと置き換え」なので、送らないことを徹底する
（`docs/google-field-gap.md`）。

タスクは Calendar とは独立した同期経路を持つ。予定側の同期失敗がタスク側に波及しない。
